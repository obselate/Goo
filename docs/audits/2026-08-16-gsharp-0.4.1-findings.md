## Method

Every historical source under `probes/Findings` was copied to one temporary directory. Every
temporary project was pinned to `Gsharp.NET.Sdk/0.4.1`, built in Release with warnings as errors,
and executed when compilation succeeded. Finding 08 received only this required 0.4.1 nullable-flow
change in the temporary copy:

```gsharp
guard let value = factory() as IntBox else { return 1 }
```

The original finding sources and project files were not changed. Temporary sources, outputs, logs,
and the official-history clone were deleted after the evidence below was captured.

Source digests are SHA-256 over each finding's `.gs` bytes concatenated in lexical path order. The
matrix used .NET SDK 10.0.111 and runtime 10.0.11 on Linux x64.

## Package-boundary finding 19

The expanded T01 consumer found one 0.4.1 behavior that the historical matrix did not cover. An
external G# subclass of `Cell[TInput]` can override `ShouldRebuild(TInput,TInput)` correctly, but an
inherited access to `Input` is bound as `object`. Direct `Input.Value` fails with GS0158. An explicit
`PackageInput(Input)` conversion compiles, but emitted IL casts the receiver through
`Cell[object]`, so that source is not a valid runtime workaround.

Goo retains the existing `Input` property for current same-assembly behavior and adds a typed
`Build(input TInput)` dispatch bridge for external G# cells. Existing parameterless `Build()` cells
remain valid. A freshly packed normal NuGet consumer mounted an external input cell, executed its
typed build, and completed native SDL open, pump, close with zero build warnings or errors.

## Conclusion

All 18 historical findings and the new package-boundary finding have an explained official 0.4.1
disposition. Finding 19 is covered only by the existing T01 package consumer because it is a real
cross-assembly end-to-end behavior. The temporary historical matrix is not part of the normal suite.
The 0.4.1 source migration may proceed with the retained workaround decisions above, subject to the
existing package, behavior, API, documentation, and allocation gates.
